# Citation Plot Call-outs Design

## Goal

Make applicants easier to identify in both citation-versus-age plots by giving every plotted applicant a distinct color and adding surname call-outs for the 15 most-cited plotted applicants.

## Considered approaches

1. **Shared server-side plot model (selected).** Build the ranked points, surnames, and color assignments once and consume the result in both the HTML/SVG and XLSX renderers. This keeps the two report formats consistent and adds no runtime dependency.
2. **Independent web and workbook implementations.** This is smaller initially, but ranking, name parsing, and colors could diverge between outputs.
3. **Client-side charting library.** This offers automatic label placement, but adds a dependency and duplicates server-side export logic for a narrowly scoped enhancement.

## Behavior

- Preserve the current citation value rule: use total citations when present and Google Scholar citations as the fallback.
- Give every applicant record a distinct deterministic color. The same applicant uses the same color in the anagraphic-age plot, academic-age plot, and workbook charts generated from the same report dataset.
- Rank only points that can be plotted in the relevant chart. Label the 15 highest citation totals, or all points when fewer than 15 are plottable. Break citation ties by applicant name and then stable source order.
- Derive a surname label from the text before a comma in `Surname, Given` names, otherwise from the final whitespace-delimited name token. Ignore common trailing generational suffixes. Preserve hyphens and diacritics.
- Keep full applicant names, age values, and citation totals in accessible point descriptions. Color and surnames are enhancements, not the only identity channel.

## Web rendering

- Continue using dependency-free inline SVG.
- Render every marker with its shared point color.
- Render the selected surname labels in left and right call-out lanes, ordered vertically to reduce crossings. Wrap long or hyphenated surnames inside their lane without clipping. Connect each label to its marker with a colored leader line over a high-contrast halo.
- Give every colored marker a high-contrast outline in all four supported skins.
- Keep the two existing report cards, titles, axes, responsive behavior, table, filter, sorting, and modal unchanged.

## Excel rendering

- Continue using native Excel scatter charts generated by `openpyxl`.
- Use one one-point series per plottable applicant so each marker can carry the shared applicant color.
- Show series-name data labels only for the top 15 plotted applicants; use the derived surname as the series name. Keep the legend hidden and the source data table intact.
- Give every marker a dark contrasting outline and reserve axis headroom so the surname labels remain inside the native chart boundary.

## Verification

- Unit-test surname derivation, ranking, tie behavior, per-record color uniqueness, and cross-chart color consistency.
- Assert that each web chart contains the expected number of colored markers and exactly 15 surname call-outs for a dataset of more than 15 complete records. Exercise long hyphenated surnames and verify every rendered label stays inside its SVG and viewport.
- Check marker and leader-line contrast against every supported skin's chart surface.
- Assert that each workbook chart contains one series per plottable point, distinct marker colors, and data-label configuration for exactly the top 15 series.
- Run the focused tests, full test suite, browser accessibility checks, responsive overflow checks, and a Microsoft Excel render inspection of both workbook charts.

## Scope boundaries

- Do not change applicant records, citation calculations, authorization, filtering, sorting, export auditing, invitations, or email behavior.
- Do not alter the approved portal specification or earlier implementation plans.
